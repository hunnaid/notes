# Lecture 1: Anatomy of a manipulation system

## What is Manipulation?

### Definitions
* **Etymological:** Activities performed by hands
* **Open-World Manipulation:**
  Beyond narrow pick-and-place, open-world manipulation requires:
  * Rich perceptual understanding of unstructured scenes.
  * Common-sense spatial and physical reasoning about objects.
  * Long-term (task-level / symbolic) plans combined with fine (joint-level / continuous) motions.

### Core Conceptual Scope
* **State Representation:** Manipulation is not just controlling arm coordinates. The relevant state space is:
  $$\text{State of the Robot} \times \text{State of the Environment}$$

* **Beyond Pick-and-Place:** Encompasses continuous, contact-rich dynamic interactions (e.g., dishwashing, wiping, tool use, manipulating articulated objects like drawers/doors).
* **Belief State in Pick-and-Place:** Even pick-and-place requires belief-space reasoning when occlusions and hidden states exist (e.g., searching for Spam in closed drawers).
* **Dexterity vs. Generality Spectrum:** A fundamental trade-off exists between specialized dexterous end-effectors/trajectories and general-purpose systems.

## Hardware: Anatomy of a Manipulator

A physical robotic manipulation system consists of kinematic chains, dynamic actuators, and sensory feedback loops.

* **Kinematic Elements:**
  * **Links:** Rigid bodies connecting joints.
  * **Joints:** Revolute (rotational) and Prismatic (linear).
* **Actuation & Transmissions:**
  * **Motors:** Electric or hydraulic.
  * **Transmission:** Introduces non-ideal dynamics including gear reduction ratios, backlash, and joint friction.
  * **Motor Drivers:** Operated in position control mode or direct torque control mode.
* **Sensory Modalities:**
  * **Proprioception:** Joint encoders (positions, velocities) and motor torque sensors.
  * **Contact / Tactile:** Wrist force/torque sensors, tactile fingertip arrays.
  * **Exteroception (Vision):** RGB-D depth sensors, laser scanners / LiDAR.

## System Architecture & Control Paradigms

### Hierarchical Decomposition
Standard systems operate across three primary temporal bands:

| Frequency Band | Perception Components | Decision-Making Components | Typical I/O |
| :--- | :--- | :--- | :--- |
| **Slow (< 1 Hz)** | 3D mapping, object pose/mesh estimation, human intent estimation. | Mission planning, symbolic task scheduling, task-level subgoals. | User input, goals $\to$ discrete actions. |
| **Medium (1–100 Hz)** | Object recognition, point cloud tracking, surface registration. | Motion planning, inverse kinematics, trajectory optimization (e.g., RRTs). | Cameras/LiDAR $\to$ paths and trajectories. |
| **Fast (> 100 Hz)** | Joint state filtering, contact state estimation. | Joint tracking control, impedance control, visual servoing. | Encoders/Torque $\to$ actuator torques. |

### Alternative: End-to-End Visuomotor Policies
Directly learn a policy mapping sensor inputs to actuator commands without an explicit pipeline decomposition:
* Image Observation ($\mathbb{R}^{H \times W \times C}$) $\to$ Perception Network (often pre-trained) $\to$ Latent Feature State ($\mathbb{R}^{32}$).
* Policy Network combines latent features with robot state to predict continuous actions ($\approx \mathbb{R}^7$).

## Introduction to Drake

[Drake](https://drake.mit.edu) is a C++ and Python framework for dynamical systems modeling, non-linear optimization, and contact simulation.

### Key Capabilities
* **Deterministic Simulation:** Reproducible dynamics and contact execution.
* **Systems Framework:** Graph-based computational architecture via `LeafSystem` and `Diagram`.
* **Optimization Integration:** Native mathematical programming solvers (MathematicalProgram).
* **Hydroelastic Contact Model:** Robust contact physics modeling compliance and pressure distributions without rigid-body chatter or stiffness instabilities.

### Core Abstractions
* **`LeafSystem`:** Atomic building block implementing input/output ports, state declarations, and differential equations.
* **`Diagram` & `DiagramBuilder`:** Multi-system composite graph wired via ports.
* **`Context`:** Explicit data container containing system time, continuous/discrete state, parameters, and input port values. *Systems themselves remain stateless; all state is passed via the `Context`*.
* **`MultibodyPlant`:** Drake's multi-body dynamics subsystem for rigid/flexible mechanisms.
* **`SceneGraph`:** Manages geometry, visualizers, and collision detection.

## Drake Code Reference

### Example 1: Static / Memoryless `LeafSystem`
```python
from pydrake.systems.framework import BasicVector, Context, DiagramBuilder, LeafSystem

class DoubleSystem(LeafSystem):
    def __init__(self):
        super().__init__()
        # Declare input and output ports
        self.DeclareVectorInputPort("u", 1)
        self.DeclareVectorOutputPort("y", 1, self.CalcY)

    def CalcY(self, context: Context, output: BasicVector) -> None:
        u = self.get_input_port().Eval(context)
        output.SetFromVector([2.0 * u[0]])

# Connecting systems into a Diagram
builder = DiagramBuilder()
sys1 = builder.AddSystem(DoubleSystem())
sys2 = builder.AddSystem(DoubleSystem())

builder.Connect(sys1.get_output_port(0), sys2.get_input_port(0))
diagram = builder.Build()
```

### Example 2: Continuous Dynamic System & Simulation
Models a 1D vertical mass under gravity:
$$
\dot{z} = v
$$

$$
\dot{v} = g + \frac{f}{m}
$$

```python
from pydrake.systems.analysis import Simulator
from pydrake.systems.framework import (
    BasicVector,
    ContinuousState,
    Context,
    DiagramBuilder,
    LeafSystem,
)
from pydrake.systems.primitives import LogVectorOutput

class VerticalMassUnderGravity(LeafSystem):
    def __init__(self, gravity: float = -9.81, mass: float = 1.0):
        super().__init__()
        self._g = float(gravity)
        self._m = float(mass)

        # Continuous state: [position z, velocity v]
        self.DeclareContinuousState(2)

        # I/O ports
        self.DeclareVectorInputPort("force", 1)
        self.DeclareVectorOutputPort("position", 1, self.CalcPosition)

    def CalcPosition(self, context: Context, output: BasicVector) -> None:
        x = context.get_continuous_state_vector()
        output.SetFromVector([x[0]])

    def DoCalcTimeDerivatives(self, context: Context, derivatives: ContinuousState) -> None:
        # Extract state [z, v]
        x = context.get_continuous_state_vector().CopyToVector()
        z, v = x[0], x[1]

        # Evaluate input port force f
        f = self.get_input_port(0).Eval(context)[0]

        # Derivatives: [z_dot = v, v_dot = g + f/m]
        z_dot = v
        v_dot = self._g + (f / self._m)
        derivatives.get_mutable_vector().SetFromVector([z_dot, v_dot])

# Build diagram & configure simulation
builder = DiagramBuilder()
mass_sys = builder.AddSystem(VerticalMassUnderGravity())
logger = LogVectorOutput(mass_sys.get_output_port(0), builder)
diagram = builder.Build()

# Context configuration
ctx = diagram.CreateDefaultContext()
# Set initial state: z = 10.0, v = 0.0
ctx.get_mutable_continuous_state().SetFromVector([10.0, 0.0])

# Fix external input force on the subcontext
sys_ctx = mass_sys.GetMyContextFromRoot(ctx)
mass_sys.get_input_port(0).FixValue(sys_ctx, 10.0)

# Run simulation
sim = Simulator(diagram, ctx)
sim.AdvanceTo(2.0)

z_final = mass_sys.get_output_port(0).Eval(sys_ctx)
print("Final position [z] =", z_final)
```

### Example 3: Loading Manipulators with MultibodyPlant and SceneGraph
```python
from pydrake.multibody.parsing import Parser
from pydrake.multibody.plant import AddMultibodyPlantSceneGraph
from pydrake.systems.framework import DiagramBuilder

builder = DiagramBuilder()

# 1. Instantiate MultibodyPlant alongside SceneGraph
plant, scene_graph = AddMultibodyPlantSceneGraph(builder, time_step=1e-4)

# 2. Parse model files (URDF / SDF)
parser = Parser(plant, scene_graph)
parser.AddModelsFromUrl(
    "package://drake_models/iiwa_description/urdf/iiwa14_primitive_collision.urdf"
)

# 3. Finalize plant geometry and kinematics (required before Build)
plant.Finalize()

diagram = builder.Build()
```
