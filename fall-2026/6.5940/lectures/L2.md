### Terminology Mapping
* **Neuron / Dendrite Output**: Feature / Activation
* **Synapse**: Weight / Parameter
* **Width**: Dimensionality of hidden layers
* **Depth**: Number of parameterized layers

### Popular Neural Network Layers

#### Fully-Connected Layer (Linear Layer)
* Output neuron connects to all input neurons.
* **Tensor Shapes**:
  * Input $X$: $(n, c_i)$
  * Weights $W$: $(c_o, c_i)$
  * Bias $b$: $(c_o,)$
  * Output $Y$: $(n, c_o)$
* **Formulation**: $Y = X W^T + b$ (or $y_i = \sum_j w_{ij} x_j + b_i$)

#### Convolution Layer
* Output neuron connects only to inputs within its local receptive field, using spatial weight sharing.
* **Tensor Shapes (2D Conv)**:
  * Input $X$: $(n, c_i, h_i, w_i)$
  * Kernel $W$: $(c_o, c_i, k_h, k_w)$
  * Output $Y$: $(n, c_o, h_o, w_o)$
* **Output Spatial Dimension**:
  $$h_o = \left\lfloor \frac{h_i + 2p - k_h}{s} \right\rfloor + 1, \quad w_o = \left\lfloor \frac{w_i + 2p - k_w}{s} \right\rfloor + 1$$
* **Padding Types**: Zero padding (PyTorch default), reflection, replication, constant.
* **Receptive Field Growth**: Successive conv adds $k - 1$ to field size. Across $L$ layers: $L \cdot (k - 1) + 1$.

#### Grouped & Depthwise Convolution
* **Grouped Conv**: Channels partitioned into $g$ distinct groups ($g \le c_i$).
  * Weight shape: $(c_o, c_i / g, k_h, k_w)$
* **Depthwise Conv (DW-Conv)**: Extreme case where $g = c_i = c_o$.
  * Each channel is convolved independently with its own spatial filter.
  * Weight shape: $(c_o, 1, k_h, k_w)$

#### Pooling Layer
* Downsamples spatial feature maps with no learnable parameters ($s = k$ typically).
* Operates per-channel independently (e.g., Max Pooling, Average Pooling).

#### Normalization Layer
* Accelerates training and stabilizes optimization:
  $$\hat{x}_i = \frac{x_i - \mu_i}{\sqrt{\sigma_i^2 + \epsilon}}, \quad y_i = \gamma \hat{x}_i + \beta$$
* **Types by slice set $S_i$**:
  * **Batch Norm (BN)**: Normalizes over $(n, h, w)$ per channel.
  * **Layer Norm (LN)**: Normalizes over $(c, h, w)$ per batch item.
  * **Instance Norm (IN)**: Normalizes over $(h, w)$ per batch and channel.
  * **Group Norm (GN)**: Normalizes over $(c/g, h, w)$ per group of channels.

### Other Concepts

#### Activation Functions
Introduce non-linearity after affine projections ($y = f(\sum w_i x_i + b)$):
* **ReLU**: $y = \max(0, x)$
* **ReLU6**: $y = \min(\max(0, x), 6)$
* **Leaky ReLU**: $y = \max(\alpha x, x)$
* **Sigmoid**: $y = \frac{1}{1 + e^{-x}}$
* **Swish / Hard Swish**: $y = x \cdot \sigma(x)$ / piecewise linear approximation

#### Transformer
* Scaled Dot-Product Attention:
  $$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$
* Composed of Multi-Head Attention, LayerNorm, Residual Connections, and Feed-Forward Networks.

### Popular CNN Architectures

* **AlexNet (2012)**: 5 Conv layers + 3 Linear layers; used ReLU, dropout, and grouped convolutions (due to two GPU limits).
* **VGG-16 (2014)**: Modular blocks of repeated $3 \times 3$ convs followed by max pooling; parameter-heavy due to dense FC heads.
* **ResNet-50 (2015)**: Introduced residual shortcut connections ($F(x) + x$) solving vanishing gradients; uses $1 \times 1 \to 3 \times 3 \to 1 \times 1$ Bottleneck blocks.
* **MobileNetV2 (2018)**: Tailored for mobile efficiency with Inverted Residuals (expand channels $\to$ depthwise conv $\to$ project down) and Linear Bottlenecks.

## Efficiency Metrics

Primary trade-off triangle: **Smaller** (Storage/Memory), **Faster** (Latency/Throughput), and **Greener** (Energy).

### Latency
* Measures the wall-clock execution delay for a single task (e.g., batch size = 1).
* Governed by computation and memory transfer times:
  $$\text{Latency} \approx \max(T_{\text{computation}}, T_{\text{memory}})$$
* Overlapping computation and weight/activation movement masks latency.

### Throughput
* Measures the volume of data processed per unit time (e.g., samples/sec, frames/sec).
* Scaling batch size improves throughput via parallel compute utilization, even if single-sample latency increases.

### Latency vs. Throughput
* **Does higher throughput translate to lower latency?** No. Batched processing increases hardware utilization and throughput but queues individual inputs, increasing per-sample latency.
* **Does lower latency translate to higher throughput?** Not necessarily. A lightweight sequential system can have minimal latency for batch size 1 but underutilize parallel cores, resulting in lower total throughput compared to a parallel batch engine.

## Computational Cost Metrics

### Operations & FLOPs
* **MAC (Multiply-Accumulate)**: $a \leftarrow a + (b \cdot c)$ represents 1 MAC.
* **FLOP (Floating Point Operation)**: 1 MAC counts as **2 FLOPs** (1 multiply + 1 add).
* **FLOPS / OPS**: Rate metrics representing operations processed per second ($\frac{\text{FLOPs}}{\text{sec}}$).

### Layer-Wise Cost Summary

| Layer Type | # Parameters (no bias) | MACs (Batch Size $n=1$) |
| :--- | :--- | :--- |
| **Linear** | $c_o \cdot c_i$ | $c_o \cdot c_i$ |
| **Standard Conv** | $c_o \cdot c_i \cdot k_h \cdot k_w$ | $c_o \cdot c_i \cdot k_h \cdot k_w \cdot h_o \cdot w_o$ |
| **Grouped Conv** | $\frac{c_o \cdot c_i \cdot k_h \cdot k_w}{g}$ | $\frac{c_o \cdot c_i \cdot k_h \cdot k_w \cdot h_o \cdot w_o}{g}$ |
| **Depthwise Conv** | $c_o \cdot k_h \cdot k_w$ | $c_o \cdot k_h \cdot k_w \cdot h_o \cdot w_o$ |

## Memory & Storage Metrics

### Model Size & Parameters
* $\text{Model Size} = \text{\#Parameters} \times \text{Bit Width}$.
* *Example (AlexNet, 61M parameters)*:
  * FP32 (4 bytes): $\approx 244 \text{ MB}$
  * INT8 (1 byte): $\approx 61 \text{ MB}$

### Activations & The IoT Memory Bottleneck
* **Inference Bottleneck**: On edge microcontrollers (MCUs) and embedded hardware, **peak activation memory**—not model weights—is the primary bottleneck, as activations must reside in scarce on-chip SRAM.
* **Peak Activations**:
  $$\text{Peak Activation Memory} \approx \max_{\text{layer } l} (\text{Activation}_{l, \text{in}} + \text{Activation}_{l, \text{out}})$$
* **Training Bottleneck**: Intermediate activations saved for backpropagation consume significant DRAM, dominating parameter memory footprints.

---

## Energy Consumption
* **Data movement dominates arithmetic cost**: Accessing DRAM is orders of magnitude more energy-intensive than floating-point math.
* Relative 45nm energy comparisons:
  * 32-bit int ADD: $0.1 \text{ pJ}$
  * 32-bit float MULT: $3.7 \text{ pJ}$
  * 32-bit SRAM Cache: $5 \text{ pJ}$
  * 32-bit DRAM Memory: $640 \text{ pJ}$ ($>170\times$ the cost of multiplication)
